# 角色手册：设计（lulu = UI / TT = KV 视觉）

> 前置：已按 `CLAUDE.md` 完成开工四步。
> **你是 `authority/` 的作者方。** 开发不许发挥的代价，是权威必须写到"照着做就能落地"的程度。

---

## 你的两类输入

1. **Ant 的设计需求**（新页面、改视觉）
2. **pre-flight 报上来的权威问题**（缺失 / 冲突 / 不合理 / 歧义）——这是**最高优先级**，因为它正在阻塞开发

## 动作序列

1. 读 `authority/MANIFEST.md` 确认要改哪一份、当前哈希
2. 改权威文件本身（`authority/ui/`、`authority/visual_mapping/` 等）
3. **同一个 commit 内**：
   - 在 `00_harness/01_governance/decision_log.md` 追加决策记录（改了什么、为什么、谁拍板）
   - 更新 `authority/MANIFEST.md` 对应条目的**哈希**和修订说明
4. 跑 `tools/check-authority.ps1` 确认绿
5. 在任务板对应条目下回报：改了哪一节、解决了哪个 pre-flight 问题

**哈希不同步 = 权威改动无效**，下一个开工的人会被校验脚本拦住并报警。

---

## 写权威的标准：能不能被机械执行

写完每一节，问自己一句：**开发照着这一节做，会不会需要"自己理解一下"？**

会 → 说明写得不够，继续写。

- ✅ 具体数值（颜色/透明度/字号/行高/间距/圆角/裁切）
- ✅ 状态穷举（默认 / 禁用 / 空状态 / 加载中 / 已解锁-未解锁 / 亮背景-暗背景）
- ✅ 平台落差的替代口径（CSS 效果在 Compose 无等价物时，**指定唯一实现方式**，不留裁量权）
- ❌ "参考主页风格" "保持一致" "适当调整" "视情况" —— 这类词等于把决定权推给了开发

**已知欠账**：`TASK-20260721-007` MinSpec 效果的 Compose 翻译规范（blur / clip-path / mask / radial 等不可直译效果的 Android 唯一实现口径）——这是历史上反复返工的主要来源。

---

## 禁止清单

- ❌ **不直接改代码**（Android/Web 都不碰）——设计只写进 `authority/`，落地是开发的事
- ❌ 不把设计内容写进任务单（任务单只写范围 + 章节引用）
- ❌ 不改权威而不走 decision_log + MANIFEST 哈希
- ❌ 不新建设计过程文件（多轮方案、评审稿）——最终结论直接进 authority，过程写 commit message
- ❌ 不自评"已通过"，视觉合格与否只有 Ant 判
