## P0-1 普通节点必须去掉卡片底

**现状**：每个小节都是一张半透明灰色圆角/切角卡片，整页是卡片网格。  
**权威**：§27.2「不得退化为方块卡片网格」；§27.9.1。

普通小节的正确形态是 **点 + 序号 + 标题**，没有任何卡片背景：

- 外圈 `r=18`（dp: 6），填充 `#091522`，描边 `#D7BE86` 2.2，带金色外发光
- 内点 `r=4.5`，`#D7BE86`
- 序号：圆心水平偏移 `±35`，`y = cy − 8`，13，letter-spacing 2，`#D7BE86`
- 标题：同 x，`y = cy + 22`，22，weight 550，`#F4EEDF`
- 标题必须带文字描边 `#07111E` 5px @0.8 —— 这是压在背景图上还能读清的关键，别用卡片底代替

只有**关键剧情节点**才是配图卡（§27.9.2），普通节点一律不是。

## P0-2 连接路径整条补上

**现状**：完全没有连线，只有卡片上下堆叠。  
**权威**：§27.3「保持 v7 的折线路径」；§27.10。

- 主路径：`#D7BE86`，宽 2.6，opacity 0.76，round cap/join
- 弱路径：`#DCE4ED`，宽 1.4，opacity 0.18
- **只用正交折线**（水平段 + 垂直段直角相接），不用曲线不用斜线
- 必须真实连接相邻节点圆心，不是背景装饰

第四部参考图（`Page_04_WorldCup_v7.png`）是最清楚的样例：01 → 02 → 03 → 04 由一条金色直角走线串起来。

几点补充：

- **Q1 不与 §27.1 冲突**。§27.1 禁的是把 PNG / SVG 文件复制进 `res/` `assets/` 或运行时加载、从预览图裁缩略图。把里面的数字转写成 Kotlin 布局常量，正是 §27.1 要求的「以原生 UI 组件重建」。转写结果落成布局配置（如 `StoryMapLayout.kt`），不引用任何图片文件，转写完由 lulu 对照 v7 PNG 逐章验收构图。
- **Q3 的判断依据**：`他的名字，由我来写` 在 `，` 处断且丢标点，`花园别墅·秘密基地` 在 `·` 处断且丢标点——看着像「标点处断」；但 `我不是不想这样赢` 根本没标点，`夏窗·签约桌上的好麻烦` 在词中断且保留了 `·`。所以规则不成立，只能给表。你判断得对，谢谢标出来。
- **Q5 的坑**：`part4.title` 是 `世界看见他篇：U-20世界杯与豪门招募`，而 v7 第四章页头是 `世界杯` + `从追加名单到生死局，他重新站回世界的视线中央。`——两者无关。地图页页脚翻章条的章节名也用短标题（`世界杯`），不是 `第四部`；但总览页地标卡的副标题仍用 `第一部` 这种序数写法，两处别混。
- **红线确认**：断行表和文案表都属 UI 呈现配置，写在布局常量或 string 资源里，**不回写 `chapters.json`**。你不动 story-data 是对的。
