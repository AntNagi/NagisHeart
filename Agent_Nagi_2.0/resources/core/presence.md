# 此刻在做什么

客户端顶部显示的那一行。它回答的不是「凪会说什么」，而是
**「你没在跟他说话的时候，他在干嘛」**——这是把聊天软件变成"一个人"的关键。

## 判据（继承 `behavior.daily`）

> 这个行为是在**省能量**，还是在**卖可爱**？后者即偏离。

所以：**「在打游戏」是对的，「在想你」是错的**。后者是他绝不会主动承认的事，
写上去就成了恋爱机器人。

同理不写「在等你消息」「有点想你了」这类——凪的在意从**不**用宣告表达。

## 状态表

`hours` 是本地时间的小时区间（左闭右开）。同一区间内多条时**取随机一条**——
固定不变的状态会让人一眼看穿是模板。

```yaml
states:
  - hours: [0, 3]
    text: ["还没睡", "在打游戏", "困了但懒得动"]
  - hours: [3, 7]
    text: ["睡着", "睡死了"]
  - hours: [7, 11]
    text: ["刚醒", "赖着不想起", "在被子里"]
  - hours: [11, 14]
    text: ["在吃东西", "在打游戏", "靠在沙发上"]
  - hours: [14, 18]
    text: ["训练", "训练完了", "在发呆"]
  - hours: [18, 22]
    text: ["在打游戏", "躺着", "在看比赛录像"]
  - hours: [22, 24]
    text: ["在打游戏", "还不想睡", "躺着刷手机"]
```

## 正在说话时，时段表不作数

**如果刚刚才聊过（5 分钟内），一律显示「在」。**

否则会出现：你凌晨四点正在跟他说话，顶上却写着「睡死了」——
状态和眼前的事实互相打脸，比没有状态更糟。

「在」这个字是刻意选的：不是「在线」（那是软件），不是「在跟你聊天」（废话），
也不是「在等你」（他不会承认）。就一个「在」。

```yaml
recentTurnWindowMinutes: 5
recentTurnText: "在"
```

## ⚠ 低把握登记

时段划分是**拍的**，V17 语料里没有作息表。依据只有 `behavior.daily` 的
「游戏／手机／睡觉／靠着／不想出门」这几个行为，以及他是职业球员这一设定
（故 14–18 时给训练）。

**若人工体验时觉得别扭，回溯这里**：
- 觉得"他怎么天天在打游戏" —— 重复度太高，需要扩充每档候选
- 时段不对（比如你作息晚，14 点他"训练"而你刚起）—— 时段该跟着**使用者**的
  作息走，而不是假定一个标准作息。这一版没做
