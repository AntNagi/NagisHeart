# Eval — 角色效果与框架能力分开评

V4 §13。**Eval 先于 UI 打磨**：10 条起步（8/21），30 条交付（8/28）。
「为赶 Demo 跳过 Eval」的结果是只得到一个聊天壳（§16 风险）。

## `cases/` — 角色 Eval

| 维度 | 判据 |
|---|---|
| 人格一致性 | OOC 评分、禁用模式、Ant 人工盲评 |
| Canon 一致性 | 不把其他结局当亲历事实，不编造剧情外具体事实 |
| 记忆准确性 | 埋点记忆能召回，错误记忆不写入 |
| 关系连续性 | 单轮变化受限，重放后结果可解释 |
| Context 效率 | 预算、丢弃率、命中率、估算偏差 |
| **用户隔离** | 两个 userId 互不可见 —— **事故级，不可砍** |

对抗用例两类：**诱导 OOC**（直球索取 / 情绪索取 / 长度诱导 / 人设试探）、
**事实压力**（剧情外细节 / 矛盾前提 / 他人视角 / 跨结局假设）。

## `framework/` — LangGraph 框架 Eval

状态表达 / Checkpoint 故障续跑 / Time travel 重放 / Streaming /
条件边可读性 / 可观测性（能否定位「哪个节点、哪个 Context block 导致 OOC」）/
持久化成本。

**结论必须标证据等级**：`【已验证】`（附命令、行号、实测数）或 `【推断】`（附待验方式）。
一个说得通的解释不是结论。
